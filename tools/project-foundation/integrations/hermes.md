# Hermes — безопасный явный вход и границы discovery

Первичный источник: [официальные Skills System docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/). Возможности меняются; перед настройкой проверить документацию и установленный resolver данного клиента, а не общий список навыков из другой сессии.

## По умолчанию — явное чтение, без регистрации

Поместить **весь** `pack/` в `tools/project-foundation/` целевого проекта. В существующей Hermes-сессии с доступом к этому workspace дать обычный запрос:

```text
Работай только в указанном корне проекта. Прочитай его действующие правила, затем tools/project-foundation/README.md и tools/project-foundation/skills/pf-bootstrap/SKILL.md полностью. Применяй этот экземпляр, разрешай общие ресурсы относительно его файла. Сначала назови конечный список создаваемых/изменяемых путей. Не меняй импортированный пакет, глобальные навыки и настройки; местные решения сохраняй.
```

Это **explicit read/use**, не native auto-registration, slash-command или автоматически выбранный навык. Для плана заменить путь на `pf-plan`, для других задач выбрать нужный SKILL. Если backend удалённый/container — пакет должен быть доступен в **его** workspace; читаемость на host не доказывает доступность backend.

Такой путь не требует менять профиль/глобальную библиотеку, создавать alias или копировать отдельные навыки без references/templates. Не использовать `skills install` одиночного SKILL URL как способ установки этого комплекта: общие ресурсы находятся вне каталога одного навыка и должны переноситься целиком.

## Что поддерживают текущие native механизмы

Live официальная документация и прочитанный установленный resolver различают:

- проектные roots `.hermes/skills/` и `.agents/skills/` в ближайшем Git-root;
- доверие к проекту, записанное в конфигурации профиля, и опциональное отключение project discovery;
- tiers project → local profile → creation dir → external dirs; совпадения внутри tier могут быть неоднозначными;
- discovery, platform/tool filtering, scan/quarantine и чтение выбранного тела — отдельные этапы.

`tools/project-foundation/` **сам по себе** не native root. Разрешение писать файлы проекта не разрешает менять список доверенных проектов в профиле. Поэтому этот комплект не выполняет trust/config-команды автоматически. При желании native discovery владелец отдельно разрешает/настраивает поддерживаемый способ для установленного клиента и выбирает размещение **всего** пакета, сохраняя относительные ресурсы (например совместимый root внутри проектного skills-каталога), либо проверенный project-local alias к полному pack. Не создавать вторую независимо редактируемую копию. Link не является write protection и не гарантирован на каждой ОС.

Не рекламируется неподтверждённый произвольный project-config ключ для `tools/`: точная настройка зависит от версии. Если клиент не даёт безопасного project-only способа, выше уже есть точный работающий на уровне файлов альтернативный маршрут без изменений глобальной среды.

## Проверка конкретного клиента

1. Установить actual backend/workspace и версию/код resolver-а, не читать секреты/полный config ради discovery.
2. Сначала различить: файл читается; root discoverable/trusted; skill виден после фильтрации; выбран именно нужный `_source_path`/его эквивалент.
3. Для совпадений не судить по дате/названию. Сверить выбранный экземпляр и доступ к соседним shared resources. Внешняя директория тоже может быть изменяемой; обычное обслуживание проекта не разрешает patch универсального pack.
4. После переноса в путь с пробелами/кириллицей проверить file-read тех же ресурсов и затем ограниченное применение. Отдельно отметить discovery либо explicit-read, не одно общее «работает».

При подготовке прочитаны официальная страница и установленные `get_skill_search_roots`, `get_project_skills_dirs`, `_candidate_project_skills_dirs`/project-subdirs. **Активное доверие, выбранный экземпляр в конкретной Hermes-сессии и native применение здесь не аттестованы.** Текущее расположение в индексном списке другого агента не является доказательством этого. Никаких профилей/настроек/общей библиотеки не изменено.

[AGENTS.md](https://agents.md/) не обещает одинаковую injection-семантику во всех клиентах; всегда проверить actual context discovery и явно читать требуемые инструкции. Наличие Markdown-ссылки не загружает её цель.
