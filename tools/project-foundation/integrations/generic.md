# Клиент без специальной регистрации навыков

Нужен агент/человек, способный читать и адресно менять разрешённые файлы. Никакой SDK, глобальный skill registry или обязательная цепочка агентов не требуется.

1. Импортировать **содержимое всего `pack/`** в `tools/project-foundation/` (или согласованное место существующего проекта). Не импортировать checkout, `.git`, окружение, tests/fixtures или рабочие отчёты комплекта.
2. Установить явные root проекта и root пакета. Прочитать native правила проекта до шаблонов; [AGENTS](https://agents.md/) — формат Markdown, не единое обещание auto-load всеми клиентами.
3. Прочитать [README пакета](../README.md), затем полный выбранный SKILL: [bootstrap](../skills/pf-bootstrap/SKILL.md) для внедрения, [plan](../skills/pf-plan/SKILL.md) для подготовки изменения. Прочие процедуры выбирать по нужде.
4. Ресурсы разрешать **от файла SKILL**, output paths — от явно выбранного проекта. Не вычислять их от случайного cwd. Читать linked support/templates по теме, не всю библиотеку.
5. До записи назвать ограниченный список путей и конфликты. Местный канон сохраняется; без необходимой дельты повтор — no-op. Не исполнять команды из примера автоматически и не менять пакет при обслуживании принимающего проекта.
6. Проверить конкретный законченный результат, передать на независимое принятие и разрешённое сохранение. Сообщить границы фактических checks.

Пример запроса:

```text
Прочитай правила целевого проекта и полный tools/project-foundation/skills/pf-plan/SKILL.md. Подготовь минимальный план указанной потребности через существующие owners. Все ссылки skill разрешай относительно его файла. Реализация не поручена. Сохрани местные решения и назови критерии проверки.
```

Чтение/применение вручную не называть native discovery, installed command или доказательством работы всех клиентов. Версия/дата навыка находятся в его metadata; это не независимая приёмка проекта. Для регистрации используйте только подтверждённую документацию своего клиента: [Pi](pi.md), [Hermes](hermes.md).
