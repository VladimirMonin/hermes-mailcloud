# Приложение: web / React

Читать только для web-поверхности вместе с [UI-навыком](../SKILL.md). Это вопросы к
существующей архитектуре, не библиотека компонентов и не предписание нового стека.

## Семантика и фокус

Найти принятые Form/Field/Dialog/Button, tokens/theme и маршруты. Действие — button,
переход — ссылка, поле — связанный label, ошибка — понятная связь с полем и способ
исправления. Нативная HTML-семантика предпочтительнее механической россыпи ARIA.
Проверить видимый focus, порядок клавиатуры, доступные имена/ошибки и применимые
contrast/reduced-motion/touch условия. Автоматический scan не доказывает весь сценарий.

Модальный диалог должен быть реально модальным: фон недоступен для взаимодействия,
Tab/Shift+Tab остаются внутри, initial focus осмыслен, Escape работает по принятому
контракту, после закрытия focus возвращается уместно. Один `aria-modal` не trap.
Использовать существующий проверенный dialog, не копировать короткий учебный JSX,
который умеет лишь initial/return focus. Проверить взаимодействие, не только DOM.
Первичный справочник: [W3C APG Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

## Размеры, контент и переходы

Выбрать viewport-условия из задачи/поддержки проекта, не универсальные «375 и 1440».
В затронутой области проверить длинные подписи/данные и локализацию, перенос/scroll,
основное действие, стабильность размеров при loading/error и применимые narrow/wide
условия. Не заменять принятую тёмную тему новой светлой из личного вкуса. Screenshot
показывает только названное состояние/условие, не все breakpoint-ы.

Для формы рассмотреть ошибки и повтор после исправления; для таблицы — empty,
loading, partial/error и выбор/фильтр, если они есть. Обычная подпись не требует
аудита всех маршрутов. Непроверенное из-за отсутствия доступа не становится N/A.

## Асинхронность без второго owner-а

Использовать действующие data-fetch/cache/state/operation механизмы. Не заменять
framework fetching самописным Effect ради примера. При ручном Effect проверить
cleanup и защиту от out-of-order responses; официальный
[React useEffect — Fetching data with Effects](https://react.dev/reference/react/useEffect#fetching-data-with-effects)
показывает этот риск, не универсальную замену архитектуры.

Последовательность A→B, B завершился, поздний A: проверить, что реальное применение
результата следует текущей identity. Unmount/смена входа освобождают свои подписки
и не применяют устаревший ответ. Отмена/retry принадлежат существующему owner-у;
не обещать отмену underlying операции по одному скрытию spinner-а. Optimistic rollback
при отказе не должен безусловно восстанавливать весь устаревший массив поверх новой
операции; ожидание берётся из принятого контракта.

## Свидетельства и выход

- **Source**: чтение настоящих components/handlers/owners и найденная связь.
- **Rendered**: фактически рассмотренный browser result, размер/состояние/наблюдение.
- **Interaction**: keyboard, modal/focus/return и существенное действие выполнены.
- **Behavioral**: реальный owner и consumer применяют нужные данные/ошибку/stale.

Один слой не заменяет остальные. Нет браузера — полезный design/source результат,
rendered/interaction NOT_RUN с конкретным остатком. Использовать разрешённые tools
проекта; не устанавливать Playwright/React/MCP ради Markdown. Общая изоляция и
privacy — [quality](../../../references/quality.md). Первичные React/W3C ссылки здесь
библиографические, большие тексты/компоненты из них не включены. Происхождение
адаптированной процедуры — [UPSTREAM](../../../UPSTREAM.md).
