# Минимальное внедрение: учебная CLI

Это законченный пример адаптации, не отчёт о запуске. Даты учебные, результаты
команд здесь — **NOT_RUN**. Вход сверяется с реальным проектом перед применением.
В рассматриваемом входе `main.py` использует stdlib argparse, требует имя и печатает
`Hello, <name>!`. Готовых тестов, упаковки, API и GUI нет.

Достаточное дерево (не квота для каждого проекта):

```text
project/
├── main.py
├── AGENTS.md
└── docs/
    └── engineering.md
```

Если README уже достаточно хранит эти знания, отдельный engineering.md не нужен.
Философия, архитектура, проверки и диагностика — роли/разделы, не четыре обязательных
файла. Отдельный profile YAML тоже не нужен при достаточном owner-е команд/ограничений.

```markdown
Сохранять существующее поведение, если задача не разрешает его менять.

Для малой правки достаточно короткой постановки и адресной проверки.
Отдельный архитектурный документ нужен лишь при самостоятельном решении.
Приёмка и сохранение следуют действующим полномочиям проекта; навык не назначает
дополнительного reviewer-а и не отменяет обязательную независимую проверку.

Устойчивую дельту отражать в основном документе. Без новой потребности повтор —
no-op без изменения дат. Публикация, зависимости и платные сервисы не разрешены.
```

```markdown
# Инженерные решения

## Назначение и границы

Учебный вход принимает обязательное имя через argparse и печатает приветствие
Hello, <name>! из main.py. API, GUI, база данных и распространение не заявлены.
Проверка конкретной рабочей копии выполняется отдельно.

## Архитектура

Один stdlib CLI-вход. Общее ядро и система адаптеров пока не нужны.
Абстракция обосновывается настоящей обязанностью, не возможным будущим GUI.
Неизвестная семантика ошибки уточняется до изменения, не объявляется контрактом.

## Проверки

Готового тестового runner-а нет. После чтения main.py разрешённый stdlib smoke
может вызвать python -I -B main.py Example и проверить Hello, Example!.
В этом учебном тексте результат — NOT_RUN, команда не объявлена проверенной.
При баге нужен конкретный неверный исход и проверка настоящего CLI-пути.
Не выдумывать pytest или npm test.

## Диагностика

Для простого приветствия отдельные файловые журналы не нужны. При добавлении
диагностики не хранить секреты и реальные пользовательские входы без основания.
Новая обязанность хранения требует понятной потребности и owner-а.

## Изменения и знания

[Правила работы](../AGENTS.md) ведут сюда. Принятое устойчивое поведение отражать
здесь либо в уже существующей пользовательской справке. Малый fix не требует ADR.
Отдельная форма нужна только для самостоятельного долговечного знания.
Повтор без новых требований — no-op, даты не меняются.

## Ограничения

Это учебная адаптация, не приёмка программы. Предложение --uppercase остаётся
будущим: пользователь, сценарий, важный отказ и критерии задаются до реализации.
Ни дата, ни draft-паспорт не свидетельствуют о выполнении команды.
```
